# 云计算课程设计：两人协作与上传规则

> 项目名称：cloud-course-design  
> 适用课程：云计算技术课程设计  
> 协作方式：两人按“任务”为单位分工  
> 当前状态：任务暂未正式分工，后续每完成一个任务再记录负责人、复核人和完成情况  
> 核心原则：每一个任务都必须按照老师要求完成实验、保存截图、上传截图和提交代码，避免后期整理报告时缺材料。

## 1. 仓库目录规则

项目统一使用以下目录结构：

```text
cloud-course-design/
├── backend/                 # Flask 后端代码
├── frontend/                # Nginx 前端页面与配置
├── k8s/                     # Kubernetes YAML 文件
├── docs/                    # 报告、说明文档、协作规则
│   └── screenshots/         # 实验截图统一存放目录
├── docker-compose.yml       # 本地联调配置
├── .gitignore               # Git 忽略规则
└── README.md                # 项目说明
```

所有实验截图统一放入：

```text
docs/screenshots/
```

禁止把截图散放在项目根目录，也不要把截图放到：

```text
backend/
frontend/
k8s/
```

代码目录只放代码和配置，截图、报告材料统一放到 `docs/` 目录。

## 3. 按任务分工原则

本项目不采用“一个人只写代码，另一个人只写报告”的固定分工方式，而是采用：

```text
一个任务一个任务分工
```

每个任务都需要指定：

```text
主负责人 + 复核人
```

### 3.1 主负责人职责

主负责人负责该任务的主要完成工作，包括：

1. 完成该任务所需代码、Dockerfile、YAML 或命令操作。
2. 按照老师要求完成实验验证。
3. 保存该任务所有关键截图。
4. 将截图放入 `docs/screenshots/`。
5. 写出该任务的初版报告文字。
6. 提交 GitHub。

### 3.2 复核人职责

复核人负责检查该任务是否完整，包括：

1. 检查代码或配置是否能正常运行。
2. 检查截图是否符合老师要求。
3. 检查截图是否清晰，是否包含关键字段。
4. 检查报告文字是否能说明实验结果。
5. 检查是否误上传敏感信息。
6. 确认无误后，任务才算完成。

## 4. 每个任务必须上传截图的规则

每个任务完成后，必须按照老师要求保存截图，并上传到 GitHub。

截图统一路径：

```text
docs/screenshots/
```

每个任务至少要有：

```text
操作结果截图
命令输出截图
验证成功截图

```

如果某个任务没有截图，报告中就不能证明实验完成，因此该任务不能视为完成。

## 5. 截图命名规则

截图必须体现：

```text
任务编号 + 顺序号 + 截图内容
```

统一格式：

```text
任务编号-顺序号-截图内容.png
```

例如：

```text
任务1-01-docker-compose启动成功.png
任务1-02-后端api返回status-ok.png
任务1-03-前端调用后端成功.png
任务1-04-后端日志收到请求.png
任务1-05-本地镜像构建结果.png
任务1-06-SWR镜像列表.png
```

禁止使用以下模糊名称：

```text

截图2.png
微信图片.png
QQ截图.png
新建图片.png
屏幕截图.png
```

## 9. 防止代码被改乱的规则

1. 每次写代码前必须先执行：

```bash
git pull origin main
```

2. 同一时间只允许一个人修改同一个任务的核心文件。

3. 不要两个人同时修改这些文件：

```text
docker-compose.yml
backend/app.py
frontend/nginx.conf
k8s/*.yaml
docs/合作开发与上传规则.md
```

4. 如果需要修改对方正在负责的任务，必须先沟通。

5. 如果出现 Git 冲突，不要乱删代码，先截图发给组员确认。

6. 每个任务完成后再提交，不要把多个任务混在一个 commit 里。

## 10. 分支使用建议

如果只有一个人负责最终上传，可以直接使用 main 分支。

如果两个人都要提交代码，建议每个任务单独开分支：

```bash
git checkout -b task1-docker
git checkout -b task2-cce
git checkout -b task3-k8s-deploy
git checkout -b task4-pvc
git checkout -b task5-configmap
git checkout -b task6-hpa
```

分支完成后，再合并到 main。

简单规则：

```text
小改动：可以直接提交 main
大改动：新建任务分支
不确定会不会影响别人：新建任务分支
```
